## 03 描述（992 / 1000）

```
Tracks published fields on a changing source. Each observation is a node in a version chain; the change set is computed by the contract, not reported by a model.

Model work and the decision are separate: pull(watch,i) extracts one source; aggregate(watch) does the vote, diff and statuses with no model call.

Deterministic majority per field: strict majority -> CONFIRMED, a split -> DISPUTED, an empty winner -> MISSING. Never guessed.

Diff: changed_fields is computed against the parent version, so what changed and when lives on the ledger.

dispute(watch, version, source, field, claimed) re-reads the source and corrects only if a fresh read supports the claim and differs from the stored value.

A closed watch is final: pull, aggregate and dispute all refuse it.

Before storage: exact field set, bounded values, unique http(s) sources; an unretrievable source produces no reading.

39 tests cover diff, majority, correction and gates.

For compliance monitoring of published terms.
```

## 修复说明（技术细节）

### 1. `dispute` 缺少状态检查

`pull` 和 `aggregate` 都有：

```python
if w["state"] != ACTIVE:
    raise gl.vm.UserError("Watch is closed")
```

**`dispute` 漏了这一行** —— 所以 `close_watch` 之后仍能改写历史记录。现在 `dispute` 一开头就拒绝，错误消息与另外两个完全一致。

### 2. 回归测试（Steward 点名要的那一条）

`tests/direct/test_change_ledger.py` → `test_dispute_after_close_fails_and_changes_nothing`

流程：开 watch → `pull_all` → `aggregate` → `close_watch` → 尝试 `dispute`。

断言三层：
1. `dispute` **抛异常**
2. `get_reading(wid,1,0)` / `get_version(wid,1)` / `get_watch(wid)` **三个快照与调用前逐字节相同**
3. 显式再查 `values` / `status` / `latest_version` 三个字段未变，且 `state == "CLOSED"`

### 3. 提交源码与部署源码一致

Steward 要求 "matching submitted and deployed source"。做法是**部署后把源码从链上取回来逐字节比对**：

```
local   bytes: 16010  sha256: 7595bf978020713be78b7fd81df13e56fb9b32a1eb8472c3ab5e139dfa52d593
onchain bytes: 16010  sha256: 7595bf978020713be78b7fd81df13e56fb9b32a1eb8472c3ab5e139dfa52d593

BYTE-IDENTICAL: deployed source == repository source
```

方法：`genlayer code <address>` 取回链上源码，去掉 CLI 的控制台噪声（spinner 会插在源码中间），再与仓库里的 `change_ledger.py` 做 sha256 比对。
